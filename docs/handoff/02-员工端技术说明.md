# 员工端技术说明

仓库：`kaiwu-praxis`

插件包名：`kaiwu-praxis`
当前 GitHub 发布版本：`0.5.1`，标签 `v0.5.1`

## 1. 职责边界

员工端负责：

- 向 DSH 注入数字员工广场和员工设置；
- 播种并维护 7 名数字员工 preset；
- 注册 4 个本地文件工具；
- 管理每名员工的资料、SOP、技能与工具策略；
- 主动连接企业中枢，上报资产并领取配置指令。

员工端不负责：

- 企业级总览、批量管理和审计页面；
- 企业中枢 HTTP 服务和 SQLite 数据库；
- 对外开放员工电脑的入站端口；
- 保存企业管理员令牌。

## 2. 目录和入口

| 路径 | 作用 |
|---|---|
| `package.json` | DSH 元数据、导出、运行依赖和版本 |
| `cordis.patch.yml` | 将插件挂入 DSH Cordis 组合 |
| `lib/index.js` | Host 主入口；播种 preset，加载工具、策略、员工设置和企业终端代理 |
| `lib/client.js` | 无构建前端 bundle；广场、员工设置、能力卡和企业连接 UI |
| `lib/admin.mjs` | `kaiwu-praxis` settings schema、默认员工数据、文件物化、企业命令执行 |
| `lib/enterprise-endpoint.mjs` | 注册、心跳、指令领取、幂等执行与回执 |
| `lib/files-tools.mjs` | 4 个确定性文件工具的 DSH 注册层 |
| `lib/watermark-core.mjs` | PDF/图片水印底层 |
| `lib/classify-core.mjs` | 文件分类底层 |
| `lib/tool-policy.mjs` | 按员工能力设置过滤禁用工具 |
| `presets/<worker-id>/` | 每名员工的 persona、preset 和官方技能基线 |

`lib/client.js` 接近 1 MB，是从 DSH 前端注入的自注册 bundle。修改时按语义搜索函数或 UI 文案，不要依赖旧交接文档中的行号。

## 3. DSH 接入机制

插件不是独立 Web 应用。`package.json` 的 `dsh.bundle.patch` 指向 `cordis.patch.yml`，Host 侧由 DSH 加载；`dsh.client.inject` 声明前端依赖，`exports["./client"]` 提供浏览器 bundle。

前端使用 `window.__ModuleLoader__.load` 自注册，因此修改 `lib/client.js` 后无需 webpack/vite 构建，但必须：

1. `node --check lib/client.js`；
2. 在隔离 DSH profile 中重新加载插件；
3. 打开真实浏览器检查 DOM、交互和控制台；
4. 对 `dsh-better-sidebar` 已安装和未安装两种布局回归。

DSH 前端 DOM 和 slot 不是稳定公共 API。宿主升级后若入口消失或布局错位，优先检查 `lib/client.js` 中的 slot 名、选择器和挂载时机。

## 4. 数字员工模型

当前 7 名员工：

| 显示名 | ID |
|---|---|
| 水印工具 | `kaiwu-watermark` |
| 资料管家 | `kaiwu-docbutler` |
| 内容撰稿员 | `kaiwu-content` |
| 竞品分析员 | `kaiwu-competitor` |
| 情报采集员 | `kaiwu-research` |
| 品牌诊断员 | `kaiwu-brand-auditor` |
| 数据追踪员 | `kaiwu-data-tracker` |

随包基线位于 `presets/`。首次 Host 加载时，`lib/index.js` 将缺失的 preset 幂等复制到：

```text
<DSH_HOME>/.agent-presets/<worker-id>/
```

用户运行数据不应写回仓库中的 `presets/`。官方基线与用户修改的合并由 `lib/admin.mjs` 处理。

## 5. 员工设置与物化

设置命名空间为 `kaiwu-praxis`，存储在 DSH 的 settings 中。主要数据包括：

- 员工档案；
- 定时任务配置；
- 记忆；
- 资料；
- SOP；
- 技能；
- 工具策略；
- 企业连接状态。

资料和 SOP 分别物化到用户 preset 的 `knowledge/`、`sop/`；技能物化到 `skills/`；工具启停物化成工具策略和 preset 组件变化。Host watch 到 settings 更新后执行物化。

能力合并的设计目标是防止版本升级直接覆盖用户修改：

- `package`：随插件交付的官方基线；
- `local`：用户新增或修改；
- `baseVersion` / `packageVersion`：为差异升级预留；
- tombstone/删除标记：用户删除官方技能后，普通重启不会把它重新播种回来；
- “恢复”操作：显式恢复官方基线。

升级按钮和完整三方合并尚未实现，当前只有数据结构基础。

## 6. 文件工具

| 工具 | 主要能力 | 关键依赖 |
|---|---|---|
| `batch_rename` | 前后缀、序号批量重命名 | Node 文件系统 |
| `format_convert` | PNG/JPEG/WebP/AVIF/TIFF 转换 | `sharp` |
| `watermark` | 图片/PDF 水印，可输出 ZIP | `sharp`、`pdf-lib`、`fflate` |
| `file_classify` | 按规则分类和归档 | Node 文件系统 |

这些工具必须保持确定性和可复核。涉及覆盖、删除或批量移动时，要先验证目标路径并保留结果清单。

## 7. 企业连接数据流

员工端只发起出站请求：

```text
员工设置填写中枢 URL + 一次性注册码 + 终端名
  -> POST /api/enroll
  -> 中枢返回 terminalId、终端 token、企业名
  -> Host 保存 terminal.json，并从 settings 清除注册码
  -> 周期性 POST /api/terminal/heartbeat
  -> 上报员工/能力/会话快照，领取待执行命令
  -> 报告 running
  -> 修改 settings 并物化文件
  -> 本地记录执行结果
  -> 向中枢 ack succeeded/failed
```

终端身份文件：

```text
<DSH_HOME>/.kaiwu-enterprise/terminal.json
```

其中含持久终端 UUID、终端 token 和已执行命令摘要。它不进入浏览器 settings，不得放入 Git、截图或交接文档，也不要通过复制该文件来“克隆”终端。换网络不会改变终端绑定；只要保留同一 `DSH_HOME` 和身份文件，员工端恢复网络后会自动重连。换电脑或删除该状态后才需要重新注册。

幂等机制：命令执行结果先写本地状态，再发送回执。如果配置已落盘但 ack 因断网失败，下一次心跳只补发相同结果，不重复执行配置。为控制文件体积，本地只保留有限数量的执行摘要。

## 8. 企业命令范围

当前企业端可向选定终端、选定员工下发：

- 增加/删除资料；
- 增加/删除技能；
- 增加/删除 SOP。

执行入口在 `lib/admin.mjs` 的 `applyEnterpriseCommand`。新增命令类型时必须同时更新：

1. 企业端表单和 API payload；
2. 员工端命令校验与执行；
3. 物化和 tombstone 规则；
4. 幂等与失败回执测试；
5. 审计显示文案。

## 9. 安装与隔离开发

GitHub 安装：

```powershell
dsh plugin --profile <profile> add git+https://github.com/motang1219/kaiwu-praxis.git#v0.5.1
```

本地开发链接：

```powershell
dsh plugin --profile <profile> add link:E:\杰创实习\数字员工\kaiwu-praxis
```

必须为开发、员工端 A、员工端 B/C 使用不同 `DSH_HOME` 或 profile，避免 settings、preset 和 `terminal.json` 串用。便携包自身已使用独立 `home`。

## 10. 已知限制

- 定时任务目前只保存配置，未接后台调度器。
- 对话统计基于 DSH 可读取的会话快照，不是完整企业 BI。
- 工具只能启停真实声明的组件，不能在 UI 中凭空创建可执行工具。
- 自动升级、升级提示和官方基线三方合并尚未完成。
- 前端对 DSH DOM 有适配依赖，宿主升级必须实机回归。
- Windows 便携 EXE 目前没有数字签名。
- macOS 未做便携包与跨设备实机验收；当前 EXE 仅支持 Windows。
