# 阶段与成果

本文件按实际开发顺序记录已经完成的工作。测试细节与截图仍以各阶段报告为准。

## P0：员工端最小闭环

目标是验证 DSH 能否承载“数字员工”产品形态，而不是重做一个聊天应用。

完成内容：

- 建立 `kaiwu-praxis` DSH 插件。
- 建立数字员工广场、员工卡片和员工到新会话的切换链路。
- 首批 5 名数字员工：水印工具、资料管家、内容撰稿员、竞品分析员、情报采集员。
- 每位员工采用独立 preset、persona 与 `SKILL.md` SOP。
- 注册 4 个本地确定性文件工具：`batch_rename`、`format_convert`、`watermark`、`file_classify`。
- 建立早期员工管理页，支持资料、技能和 SOP 的查看维护。
- 完成真实浏览器操作和五类员工能力实测。

实现要点：

- 插件由 `cordis.patch.yml` 接入 DSH bundle。
- Host 侧在首次加载时把随包 preset 幂等播种到用户的 `.agent-presets`。
- Client 侧使用 DSH 自注册 bundle 注入 UI，无额外前端构建步骤。
- 文件类操作放在本地确定性工具中，模型只负责理解意图和组织参数。

原始证据：`E:\杰创实习\数字员工\P0实机测试\P0说明文档.md` 及其 `截图/` 目录。该目录当前位于两个 Git 仓库之外，离职归档时应一并交付或迁入项目资料库。

## P2：跨设备通信基础版

### 第一轮：单机三实例隔离验收

在一台电脑上使用三个独立 `DSH_HOME` 模拟一个企业端和两个员工端，验证协议和持久化逻辑：

- 一次性注册码；
- 员工端独立 UUID 和终端令牌；
- 心跳、资产汇总和会话计数；
- 在线批量配置；
- 离线指令排队；
- 本地幂等记录和回执补发；
- 企业中枢重启后数据保留；
- 管理员鉴权、Origin 限制和非本机监听安全门槛。

这一轮证明功能逻辑成立，但不等同于物理跨设备验收。

证据：[第一轮开发与验收报告](../../测试报告/P2-跨设备基础版第一轮/第一轮开发与验收报告.md)。

### 第二轮：远程双机实测

在两台 Windows 物理设备、两个不同网络上，通过 Tailscale 组成虚拟内网。企业中枢运行在公司电脑，远端员工端使用便携包运行。

已验证：

- 两台设备可通过虚拟内网访问中枢 `3099`；
- 两个终端同时在线并分别上报 7 名员工和能力资产；
- 在线资料同时下发到两端并以 UTF-8 正确落盘；
- 员工端离线时指令保持 `queued`，恢复后执行一次并回执；
- 中枢停止时网络节点仍可达但 `3099` 不可达，证明故障隔离有效；
- 使用原 SQLite 数据目录重启后，终端、指令和审计保留；
- 员工端无需重复输入注册码；
- Windows Tailscale 无人值守模式可避免退出远程桌面后终端掉线。

最终结果：通过。

证据：[第二轮跨设备实机测试验收报告](../../测试报告/P2-跨设备基础版第二轮/第二轮跨设备实机测试验收报告.md)。

## P3：公司内网多终端测试（通过）

目标是让公司同事在真实办公局域网中以员工端 C 接入，从而更接近最终内部部署方式，并兼作交接演示。

已完成：

- 企业中枢使用公司内网地址 `192.168.11.55:3099`，防火墙规则限制为公司网段访问 `3099/TCP`；
- 同事的 Windows 员工端 C 使用独立便携环境完成首次注册和持续心跳；
- 企业端确认终端版本、地址、7 名数字员工和能力资产；
- 在线资料下发、离线指令排队与恢复后单次执行通过；
- 企业中枢重启后，员工端未重启、未重新填写注册码即可自动恢复；
- 最终资料清理通过，员工端保持运行；
- 全流程形成 11 张截图和正式验收报告。

测试中发现：资料名称已带 `.md` 时会落盘为 `.md.md`。内容和 UTF-8 正确，但文件名不符合要求。实机先通过规范化输入完成复测，随后同时修复员工端物化逻辑和企业端负载规范化，并把员工端提升到 `0.5.1`。

`0.5.1` 候选 ZIP/EXE 已重新打包。本机从最终 ZIP 空白解压后完成浏览器、在线下发、离线队列、重启恢复、删除清理和重复扩展名回归；EXE 完成归档完整性及关键文件哈希校验。由于问题不依赖物理网络，修复后无需再组织一次跨设备重复测试。
