## 2. 已知产品限制

### 员工端

- 定时任务只有配置界面，没有后台调度执行。
- 插件升级提示、升级按钮和真正的三方差异合并没有完成。
- 工具管理只能启停已有真实工具，不能通过 Markdown 生成可执行工具。
- 对话/工作统计不是完整业务监控。
- 前端依赖 DSH 当前 DOM、slot 和内部模块，DSH 升级有版本漂移风险。
- Windows SFX EXE 未签名；macOS 交付包未完成。
- `v0.5.1` 源码已发布；本机 EXE 尚未做本轮图形化双击验收，且安装包没有代码签名。

### 企业端

- 单管理员令牌，没有用户账号、RBAC 或操作人身份。
- 无终端禁用/吊销、token 轮换、注册码手动失效。
- 无命令取消、人工重试、详情和失败诊断 UI。
- 原生 HTTP，只适合受控内网/VPN；公网需 HTTPS 网关。
- 无自动备份、数据库 schema 迁移框架、监控和告警。
- 中枢是单机 Node 进程，没有高可用或多实例协调。
- 终端在线判定依赖心跳时间，没有推送通道。

## 3. 设计债务

- `lib/client.js` 体积大且手写，前端逻辑缺少模块化和单元测试。
- 员工端 `scripts/` 过去被 `.gitignore` 忽略，本次已取消忽略；提交前仍需逐个评审并纳入 Git，确保新电脑可复现。
- 早期交接文档记录了已经过期的 commit、端口和“手工同步三副本”做法，不能继续作为发布规范。
- 便携构建目前主要依赖 `F:\dsh-build` 的人工流程，应沉淀成参数化、可审计的构建脚本或 CI。
- 企业端测试辅助脚本含特定轮次路径/IP 假设，应与产品脚本分离。

以下是明确记录过、但不应在离职前临时扩展的功能：

## 5. 出现故障时先查什么

| 现象 | 优先检查 |
|---|---|
| 企业总览全是 0 | 管理端是否填了正确回环 URL 和管理员令牌；员工端心跳是否更新 |
| 节点能 ping，3099 不通 | 中枢是否监听目标 IP、Windows 防火墙网段规则、端口是否被占用 |
| 员工端显示已连接但企业端离线 | “最后连接时间”是否持续更新；旧 UI 状态不能证明当前心跳在线 |
| 换网络后不连接 | 新网络是否能路由到原中枢地址；终端身份本身不需要重建 |
| 离线指令重复落盘 | 检查员工端 `terminal.json` 幂等摘要是否被删除或复制错环境 |
| 本机管理页访问失败 | 企业端是否同时监听 `127.0.0.1`；系统/浏览器代理是否拦截内网地址 |
| UI 入口消失或错位 | DSH 或 `dsh-better-sidebar` 是否升级，检查前端 slot/DOM 选择器 |
| 中文乱码 | 文件 UTF-8、PowerShell 5.1 BOM、stdin/stdout 编码和 HTTP charset |
| 资料名出现 `.md.md` | 确认员工端至少为 `0.5.1`，并检查企业端是否执行批量负载名称规范化 |
